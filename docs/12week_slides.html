서버서버 전체 구조

AWS 서버 1대 안에서 Docker 컨테이너 4개가 역할을 나눠 24시간 동작

/api · 로그인 → backend → db
그 외 → frontend (화면 파일)
DuckDNS사람이 읽는 이름을 서버 IP에 연결하는 무료 도메인
보안 그룹80 · 443만 인터넷에 개방, SSH는 내 IP만 허용
CaddyHTTPS 인증서 자동 발급 · 갱신(Let's Encrypt), 주소별 길 안내
frontendReact 화면 파일 제공 (실행은 브라우저에서)
backendSpring Boot: 로그인, 포트폴리오 계산 · 저장, 평일 14:00 시세 갱신
dbMySQL, 데이터 보관 (외부에 포트 비공개)

서버요청 처리와 구글 로그인

요청이 처리되는 과정
  1. 브라우저가 DuckDNS에 서버 IP를 물음
  2. 443번(HTTPS)으로 서버에 들어옴
  3. Caddy가 암호화를 처리하고 주소를 보고 나눔
  4. 화면 파일은 frontend, 데이터 요청은 backend
  5. backend가 db에서 읽거나 저장하고 응답
  6. 요청이 없어도 평일 14:00 시세를 받아 저장
구글 로그인 흐름
  1. 로그인 버튼 → 구글 로그인 화면으로 이동
  2. 비밀번호는 구글에만 입력
  3. 구글이 등록된 주소로 일회용 코드를 보냄
  4. backend가 그 코드로 구글에 직접 확인
  5. 사용자 정보 저장, 로그인 상태(세션) 생성
  6. 이후 요청은 세션으로 로그인 여부 판단

구글 규칙: 돌아올 주소는 HTTPS 필수, IP 주소 불가 → 무료 도메인 + Caddy 자동 인증서로 해결

서버보안과 운영

① 네트워크80 · 443만 개방, SSH는 내 IP만, DB · 백엔드 포트 비공개
② 통신 암호화Caddy가 받은 HTTPS 인증서
③ 사용자 인증구글 로그인, 로그인 필요한 요청은 401로 차단
④ 서버 접속SSH 키 파일로만 접속
⑤ 비밀 값환경변수 파일로 분리, 저장소에 올리지 않음
⑥ 공개 경로 정리시험용 주소 제거, 추천 API는 로그인 필수
운영하며 확인한 것
  • 서버와 로컬은 DB도 별개 → ETF 분배금 163건을 서버에 직접 입력
  • 빈 DB 기준 첫 시세 갱신 약 141초 (로그 실측)
  • 컨테이너는 서버가 켜져 있는 동안 자동 재시작되도록 설정
  • 인증서는 첫 시도에 발급, 발급 직후 몇 초 만에 자동 접속 프로그램이 들어옴
